# 一些教训

## 竞赛篇

十年 OI 一场空，**不开 `long long` / `__int128` 见祖宗**。  
大多数情况下内存是够你开 `long long` 的。

分清 0-Based Index 和 1-Based Index

`__int128` 是 GCC (4.6+ && 64 bit) Only 的  
只支持基本运算，**IO 要自己写**（不知道 `<cstdio>` 有没有 `%I128d` 之类的，`<iostream>` 拓展是简单的）

按值传递**不一定**比引用传递劣，  
（一般 64 位的架构下）指针占 $64$ 位（8 Byte）  
一般使用的整型一般情况下如下：

| 类型        | 空间 | 说明 | 大小                                                                                   |
| ----------- | ---- | ---- | -------------------------------------------------------------------------------------- |
| `int`       | 4B   | 按值 | (2e9) -2147483648~2147483648                                                            |
| `long long` | 8B   | 一样 | (9e18) -9223372036854775808~9223372036854775807                                         |
| `__int128`  | 16B  | 引用 | (1e38) -170141183460469231731687303715884105728~170141183460469231731687303715884105727 |

[禁止在 `int` 乘 `int` 时不开 `long long`](https://www.luogu.com.cn/problem/P1401)

`inline` 只适合**短函数**，长的强制 `inline` 可能导致负优化

用 `std::cin` 记得 **关同步流 & 解绑** `std::cin.tie(nullptr)->sync_with_stdio(false);` 也就 $46$ 字符对吧  
或者手写一个覆盖掉 `<iostream>` 里的更快

## 语言篇

定义指针时必须初始化为 `nullptr`。
使用指针前，一定要确保它指向的内存是合法的，`nullptr`还好，野指针/悬空指针难搞。  
`delete` 掉一个指针后，**立马把它置为 `nullptr`**。（参考 P10470，RE 调了整整一天）  
在注重稳定性、没必要使用指针且内存充裕的场合，尽量不要用语言意义上的指针，直接 数组 + `int ptr;` 模拟。

C++17 把 `register` 掐掉了

C++20 把 `std::basic_istream::operator>>(char *)` 改为 `std::basic_istream::operator>>(char &[N])`，`std::cin >> (s + 1);` 在编译阶段被掐死了（大悲）。  
所以 C++20+ 只能使用 `cin >> s;`，然后手动置后一位。  
参考帖子 <https://www.luogu.com.cn/discuss/1089935>
